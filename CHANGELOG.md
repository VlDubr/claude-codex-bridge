# Changelog

## 0.3.0

Видимость работы вызываемой модели вместо ожидания вслепую.

- `codex exec` запускается с `--json`, когда флаг поддержан: Codex стримит
  события — рассуждения, запуск команд, правки файлов, веб-поиск, обновления
  плана. Добавлен `codex-events.mjs` для разбора ленты.
- Новый инструмент `codex_progress` и команда `/codex-bridge:progress`
  показывают, чем модель занята сейчас. `codex_status` и `codex_result` тоже
  показывают ленту вместо сырых строк лога.
- `codex_ask` больше не падает по таймауту: параметр `wait_seconds`
  (90 по умолчанию), при превышении работа уходит в фон и возвращается job_id
  вместе с тем, что модель успела сделать.
- Ответ извлекается из события `agent_message`. Без `--json` поведение прежнее —
  сырой текст возвращается как есть.
- Реконнекты Codex (`Reconnecting... X/Y`) не считаются отказом.
- Тестов: 42.

## 0.2.3

Исправления по итогам запуска на Windows.

- Сбой песочницы Codex распознаётся и объясняется. Он выходит наружу как
  `user cancelled MCP tool call` или отказ MCP-инструмента, то есть выглядит
  отменой пользователя или мёртвым мостом; теперь плагин прямо говорит, что
  мост исправен, и называет причину.
- Добавлен `codex-health.mjs`: сверяет версию CLI с версиями хелперов в
  `~/.codex/.sandbox-bin`, проверяет наличие `codex-windows-sandbox-setup.exe`
  при включённой `[windows] sandbox`, предупреждает про режим `elevated` без
  прав администратора. Результат виден в `/codex-bridge:setup`.
- Настройка `bypass_sandbox` — аварийный обход через
  `--dangerously-bypass-approvals-and-sandbox`. Выключена по умолчанию,
  защищена проверкой capabilities, нераскрытый плейсхолдер её не включает.
- Тестов: 37.

## 0.2.2

- **Исправлено:** при первом запуске в проекте создавался каталог с буквальным
  именем `${CLAUDE_PLUGIN_DATA}`. Причина — избыточная передача `CLAUDE_PLUGIN_DATA`
  и `CLAUDE_PROJECT_DIR` в `env` MCP-сервера: Claude Code экспортирует их сам, а
  при несработавшей подстановке эта строка затирала правильное значение
  литералом. Обе переменные убраны из `.mcp.json`.
- Добавлен `envClean()`: нераскрытые плейсхолдеры `${...}` и пустые значения
  отбрасываются при чтении любой переменной окружения. Та же мина была заложена
  под `${user_config.*}` — незаполненное поле могло уехать в `-m` аргументом
  модели. `dataDir()` дополнительно требует абсолютный путь.
- `CODEX_BRIDGE_IMAGE_TIMEOUT_MS` переименована в `..._MIN` — значение всегда
  было в минутах, имя вводило в заблуждение.
- Английские README стали основными: `README.md`, `README_DEV.md`; русские —
  `README.ru.md`, `README_DEV.ru.md`.
- Тестов: 34.

## 0.2.1

Исправления по итогам первого прогона на живом Codex (v0.144.6).

- Уровни `reasoning effort` больше не захардкожены: набор берётся из
  `supported_reasoning_efforts` каталога модели. `gpt-5.6-sol` отвергает
  `minimal` ошибкой API — теперь это ловится до запуска, а не в виде отказа API.
- `explainCodexFailure()` переводит типовые отказы Codex в готовое действие:
  неподдерживаемый уровень усилий, истёкшая авторизация, лимит квоты,
  неизвестный флаг.
- `denoise()` убирает служебные строки Codex из сообщений об ошибках, в первую
  очередь `failed to load models cache` — рассинхрон внутреннего кэша Codex,
  который маскировал настоящую причину.
- В README добавлен раздел диагностики.

## 0.2.0

Исправления по итогам внешнего ревью. Все пункты покрыты тестами в
`tests/regressions.mjs`.

### Блокирующие
- Флаги `codex exec` определяются через `--help` и кэшируются; `--ask-for-approval`
  больше не передаётся сборкам, которые его не знают.
- Менеджер фоновых задач переписан: терминальные статусы без обратных переходов,
  код возврата в отдельном файле (переживает перезапуск), устранены гонка
  `cancel`/`exit` и утечка файловых дескрипторов.
- `job_id` валидируется по шаблону с проверкой containment — закрыт path traversal.
- `claude_task` использует `--tools` вместо `--allowedTools`, считает пересечение
  с административным allowlist и принудительно вырезает инструменты записи при
  `write: false`.
- Генератор изображений проверяет сигнатуру файла, запрещает абсолютные пути и
  `..` в `out_dir`, отклоняет `SAVED:` вне проекта и сверяет код возврата до
  поиска артефактов.
- Правка `config.toml`: замена через функцию (путь с `$&` больше не ломает блок),
  экранирование кавычек, удаление всех управляемых блоков, обнаружение конфликта
  с чужой таблицей, атомарная запись.

### Важные
- Ненулевой код возврата Codex и Claude всегда считается ошибкой, даже при
  непустом stdout.
- `exposed.json` создаётся с `0600` в каталоге `0700`; литеральные значения
  переменных окружения не копируются, поддержаны `${VAR}` и `${VAR:-default}`.
- Аргументы `/codex-bridge:setup` разбираются через `util.parseArgs` со `strict`.
- Обнаружение MCP-серверов следует precedence Claude Code: local → project → user.
- MCP-клиент реагирует на смерть сервера немедленно и сохраняет его stderr.
- Каталог моделей помечается признаком полноты; по неполному каталогу модели
  больше не блокируются.
- MCP-сервер не заявляет неподдерживаемую версию протокола, отвечает parse error
  на битый JSON и не отдаёт наружу stack trace.

### Прочее
- `defaultEnabled: false` — плагин ставится выключенным.
- Заявлены минимальные версии Claude Code (2.1.154+) и Node.js (20.11+).
- Добавлены 27 регрессионных тестов.
