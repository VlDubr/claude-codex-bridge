# Changelog

## 0.4.3

Обратный мост GPT → Claude перестал блокироваться, а проверка готовности
Codex — выполняться там, где она не нужна.

- `claude_ask`, `claude_critique` и `claude_task` запускают Claude асинхронно.
  Прежний `spawnSync` держал event loop до десяти минут: мост не отвечал на
  `ping`, не принимал отмену и выполнял параллельные вызовы по очереди. Ровно
  этот дефект был исправлен на стороне Codex ещё в 0.4.0, а на обратном
  направлении оставался.
- Отмена вызова доходит до Claude: `notifications/cancelled` останавливает
  процесс вместе с его потомками, соседние вызовы при этом продолжают идти.
  На POSIX процесс запускается своей группой — без этого потомки переживали
  убийство лидера.
- Предел на вывод считается в байтах, а не в символах строки, и при
  превышении процесс останавливается с явной ошибкой вместо тихого усечения.
- Уход моста снимает все запущенные им процессы Claude: раньше закрытие Codex
  оставляло их править файлы без надзора.
- Проверка готовности Codex стала асинхронной, с таймаутом 4 секунды на шаг,
  кэшем на минуту и защитой от параллельного запуска. Раньше два `spawnSync`
  без таймаута выполнялись перед каждым вызовом любого инструмента.
- Инструменты, которые Codex не запускают (`codex_status`, `codex_result`,
  `codex_progress`, `codex_cancel`, `codex_chats`, `codex_use`,
  `image_check_params`), проверку больше не проходят вовсе.
- Зависшая проверка возвращает отдельную причину `probe_timeout`. Раньше она
  выглядела как «Codex не установлен» — на исправном Codex это дезориентирует.
- SessionStart-хук чинит путь обратного моста до проверки готовности, а не
  после, и ограничен таймаутом 15 секунд.

## 0.4.2

- Появился CI: тесты гоняются на ubuntu-latest и windows-latest, Node 20 и 22.
  Это закрывает главный слепой участок проекта — автор работает на Windows, где
  17 тестов из 64 требуют POSIX и потому не выполнялись никогда. Отдельным
  заданием идёт `claude plugin validate . --strict`.
- Воркер помечает происхождение строк журнала. Раньше stdout и stderr писались
  в один файл, а разделялись обратно догадкой «строка начинается с `{` — значит
  событие». В JSON-режиме это работало, а на старом Codex без `--json` не
  начиналось с `{` вообще ничего, и весь вывод одновременно считался и ответом
  модели, и её диагностикой. Журналы прежнего формата читаются по старому
  правилу, чтобы задачи, пережившие обновление, не ослепли.
- Версия MCP-серверов берётся из манифеста плагина. Раньше она была записана
  строкой в четырёх местах и разошлась: `plugin.json` объявлял 0.4.1,
  `claude-bridge` представлялся как 0.3.0, а два остальных сервера — как 0.1.0.
- Верхнеуровневое описание маркетплейса добавлено: без него строгая валидация
  плагина не проходит.

## 0.4.1

- `codex_delegate` больше не уходит в фон молча: он ждёт и показывает ленту
  действий GPT, как `codex_ask`. Раньше лента прогресса была устроена только у
  ожидающих инструментов, а делегирование ждать не умело вовсе, поэтому в
  Claude Code не появлялось ни одного шага модели. Время ожидания задаётся
  `wait_seconds` (по умолчанию 120), `wait_seconds: 0` возвращает прежнее
  поведение — сразу `job_id`.

## 0.4.0

Разговор с моделями Codex и живая трасса их работы. Заодно починен фоновый
путь на Windows, где он не работал вовсе.

Исправления:

- Фоновая задача больше не запускается через `/bin/sh`: на Windows такого
  бинаря нет, задача умирала до первой строки вывода и навсегда оставалась в
  статусе `unknown`. Работу ведёт `job-worker.mjs` на Node — переносимый,
  ставит метки времени событиям, сам пишет код возврата и убивает дерево
  процессов по таймауту (`taskkill /T` на Windows, группа процессов на POSIX).
- Отказ запуска Codex теперь даёт `failed` с причиной, а не «процесс исчез».
- Убран `spawnSync`: он блокировал event loop MCP-сервера на всё время работы
  Codex, сервер не отвечал на `ping`, и клиент рвал соединение с
  `MCP error -32000: Connection closed`. Долгие вызовы стали асинхронными.
- Истечение `wait_seconds` больше не убивает первую попытку и не запускает
  работу заново: та же самая задача продолжает идти тем же процессом, а вызов
  возвращает её id.
- Сводка размышлений не обрезается до первых 100 символов.

Новое:

- `notifications/progress`: пока Codex работает, его шаги видны в Claude Code
  по мере появления — рассуждения, команды, правки файлов, поиск. Счётчик
  монотонный, без `progressToken` уведомления не шлются.
- Настройка `progress_notifications` выключает ленту, не трогая остального:
  часть сборок Claude Code закрывает соединение с MCP-сервером, получив
  `notifications/progress` (anthropics/claude-code#47378, #53617). Отрисовка
  ленты в свёрнутом виде инструмента появилась в Claude Code 2.1.153.
- `notifications/cancelled` доходит до задачи: отменённый в Claude вызов
  останавливает Codex, а не оставляет его работать в фоне.
- `codex_chat` — разговор с моделью Codex как с отдельным собеседником:
  тред продолжается через `codex exec resume`, модель, уровень reasoning и
  рабочий каталог повторяются на каждом ходе. Параллельные ходы по одному
  треду блокируются, пропавший тред даёт явную ошибку, а не молчаливое начало
  нового разговора.
- `codex_chats` — список разговоров и удаление треда.
- `codex_use` — модель и effort по умолчанию для репозитория.
- Агент `gpt-chat`, команды `/codex-bridge:chat` и `/codex-bridge:use`.
- Настройка `reasoning_summary`: при `detailed` Codex присылает сводки
  размышлений, которых при `auto` может не быть вовсе. Полные рассуждения
  модели недоступны ни при каком значении — наружу идёт только сводка.
- `scripts/statusline.mjs` — активность живых задач в строке состояния
  (подключается пользователем вручную, чужой `statusLine` не затирается).
- Аргументы и результаты чужих MCP-инструментов не пересылаются в ленту, вывод
  команд усекается: там бывают секреты и мегабайты текста.
- Тестов: 59 (17 из них требуют POSIX и на Windows помечаются пропущенными).

## 0.3.0

Видимость работы вызываемой модели вместо ожидания вслепую.

- `codex exec` запускается с `--json`, когда флаг поддержан: Codex стримит
  события — рассуждения, запуск команд, правки файлов, веб-поиск, обновления
  плана. Добавлен `codex-events.mjs` для разбора ленты.
- Новый инструмент `codex_progress` и команда `/codex-bridge:progress`
  показывают, чем модель занята сейчас. `codex_status` и `codex_result` тоже
  показывают ленту вместо сырых строк лога.
- `codex_ask` больше не падает по таймауту: параметр `wait_seconds`
  (90 по умолчанию), при превышении работа уходит в фон и возвращается job_id
  вместе с тем, что модель успела сделать.
- Ответ извлекается из события `agent_message`. Без `--json` поведение прежнее —
  сырой текст возвращается как есть.
- Реконнекты Codex (`Reconnecting... X/Y`) не считаются отказом.
- Тестов: 42.

## 0.2.3

## 0.2.2

- **Исправлено:** при первом запуске в проекте создавался каталог с буквальным
  именем `${CLAUDE_PLUGIN_DATA}`. Причина — избыточная передача `CLAUDE_PLUGIN_DATA`
  и `CLAUDE_PROJECT_DIR` в `env` MCP-сервера: Claude Code экспортирует их сам, а
  при несработавшей подстановке эта строка затирала правильное значение
  литералом. Обе переменные убраны из `.mcp.json`.
- Добавлен `envClean()`: нераскрытые плейсхолдеры `${...}` и пустые значения
  отбрасываются при чтении любой переменной окружения. Та же мина была заложена
  под `${user_config.*}` — незаполненное поле могло уехать в `-m` аргументом
  модели. `dataDir()` дополнительно требует абсолютный путь.
- `CODEX_BRIDGE_IMAGE_TIMEOUT_MS` переименована в `..._MIN` — значение всегда
  было в минутах, имя вводило в заблуждение.
- Английские README стали основными: `README.md`, `README_DEV.md`; русские —
  `README.ru.md`, `README_DEV.ru.md`.
- Тестов: 34.

## 0.2.1

Исправления по итогам первого прогона на живом Codex (v0.144.6).

- Уровни `reasoning effort` больше не захардкожены: набор берётся из
  `supported_reasoning_efforts` каталога модели. `gpt-5.6-sol` отвергает
  `minimal` ошибкой API — теперь это ловится до запуска, а не в виде отказа API.
- `explainCodexFailure()` переводит типовые отказы Codex в готовое действие:
  неподдерживаемый уровень усилий, истёкшая авторизация, лимит квоты,
  неизвестный флаг.
- `denoise()` убирает служебные строки Codex из сообщений об ошибках, в первую
  очередь `failed to load models cache` — рассинхрон внутреннего кэша Codex,
  который маскировал настоящую причину.
- В README добавлен раздел диагностики.

## 0.2.0

Исправления по итогам внешнего ревью. Все пункты покрыты тестами в
`tests/regressions.mjs`.

### Блокирующие
- Флаги `codex exec` определяются через `--help` и кэшируются; `--ask-for-approval`
  больше не передаётся сборкам, которые его не знают.
- Менеджер фоновых задач переписан: терминальные статусы без обратных переходов,
  код возврата в отдельном файле (переживает перезапуск), устранены гонка
  `cancel`/`exit` и утечка файловых дескрипторов.
- `job_id` валидируется по шаблону с проверкой containment — закрыт path traversal.
- `claude_task` использует `--tools` вместо `--allowedTools`, считает пересечение
  с административным allowlist и принудительно вырезает инструменты записи при
  `write: false`.
- Генератор изображений проверяет сигнатуру файла, запрещает абсолютные пути и
  `..` в `out_dir`, отклоняет `SAVED:` вне проекта и сверяет код возврата до
  поиска артефактов.
- Правка `config.toml`: замена через функцию (путь с `$&` больше не ломает блок),
  экранирование кавычек, удаление всех управляемых блоков, обнаружение конфликта
  с чужой таблицей, атомарная запись.

### Важные
- Ненулевой код возврата Codex и Claude всегда считается ошибкой, даже при
  непустом stdout.
- `exposed.json` создаётся с `0600` в каталоге `0700`; литеральные значения
  переменных окружения не копируются, поддержаны `${VAR}` и `${VAR:-default}`.
- Аргументы `/codex-bridge:setup` разбираются через `util.parseArgs` со `strict`.
- Обнаружение MCP-серверов следует precedence Claude Code: local → project → user.
- MCP-клиент реагирует на смерть сервера немедленно и сохраняет его stderr.
- Каталог моделей помечается признаком полноты; по неполному каталогу модели
  больше не блокируются.
- MCP-сервер не заявляет неподдерживаемую версию протокола, отвечает parse error
  на битый JSON и не отдаёт наружу stack trace.

### Прочее
- `defaultEnabled: false` — плагин ставится выключенным.
- Заявлены минимальные версии Claude Code (2.1.154+) и Node.js (20.11+).
- Добавлены 27 регрессионных тестов.
